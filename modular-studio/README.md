# Module Ground

필지를 선택하고 모듈 규격·건축 조건을 입력하면 중복도형 모듈 배치 후보와 모듈 수를 보여주는 로컬 웹사이트입니다. VS Code에서 열어 수정하고 독립 프로젝트로 GitHub에 업로드할 수 있습니다. 참고용 Mass_stacker의 원본 코드는 변경하지 않았습니다.

## 실행

Node.js 22 이상을 사용하세요. VS Code에서 **이 modular-studio 폴더를 열고** 터미널에서 실행합니다.

```powershell
npm ci
npm start
```

http://localhost:8791 에서 확인합니다. 개발 중 자동 서버 재시작은 `npm run dev`를 사용합니다. 별도의 프런트엔드 빌드나 CDN 연결 없이 예시 대지와 3D 배치가 작동합니다.

## 구현된 기능

- 가상 직사각형·모서리 절단·세장형 필지 3종
- 폭·길이·층간 반복 높이·접합 간격 입력
- 건폐율·용적률·높이·최대층수·경계 이격거리 입력
- 중앙 복도 및 단부 코어 공간 예약
- 방향·위치·배치 열 수를 바꿔 후보 탐색
- 모듈 수 우선 / 저층 우선 / 작은 건축면적 대안
- Three.js 3D, 평면 시점, 모듈 선택, 층 분리, 층별 보기
- 모듈 수·세대 환산·면적·조건 사용률·층별 목록
- 브라우저 로컬 저장, JSON 프로젝트 저장·불러오기, CSV 모듈 목록
- VWorld 주소 검색·지도 클릭·필지 경계 조회 연결 코드

**초기 규격 3.3 × 6.6 × 3.2m는 사용자 확정값이 아닌 예시입니다.** 높이는 구조·접합을 포함한 층간 반복 높이로 입력합니다. 한 세대 2개 모듈 역시 변경 가능한 가정입니다.

## VWorld 연결

필지 선택 시 파란 경계와 ‘선택한 필지’ 라벨, 주소·경계 면적·PNU 확인 패널이 표시됩니다. 지도 상단의 **일반지도 / 지적도 / 중첩 보기**로 전환합니다. 지적도는 VWorld 공식 예제의 WMS `lt_c_landinfobasemap`(LX 편집지적도) 레이어이며, 선택 필지의 벡터 경계는 그 위에 별도로 유지됩니다. 지도·지적도를 바꿔도 배치 계산용 경계 좌표는 변하지 않습니다. 발급·측량용 지적도 문서를 생성하는 기능은 아닙니다.

화면 왼쪽 **대지 주소**에서 도로명/지번 주소를 검색할 수 있습니다. ‘자동’은 두 주소 유형을 함께 조회합니다. 검색 버튼 또는 Enter를 누르면 지도 화면으로 전환해 첫 유효 검색 결과 위치로 확대하고 주황색 위치 표시를 띄웁니다. 여러 결과가 있으면 목록에서 다른 주소를 선택할 수 있습니다. 위치 팝업의 **이 위치의 필지 선택**을 누르면 파란 필지 경계를 표시하며, 확인 후 **모듈 배치 생성**을 누릅니다. 주소 검색 위치와 실제 선택된 대지는 별도로 구분됩니다.

가장 간단한 설정 방법은 화면의 **VWorld 연결**을 누르고 API 키와 등록 서비스 URL을 입력하는 것입니다. 주소 검색과 필지 API 인증이 모두 성공한 뒤 키를 서버 `.env`에 저장하고 즉시 적용합니다. 키가 이미 저장돼 있다면 키 입력란을 비워두고 등록 URL만 수정할 수 있습니다. 등록 URL은 경로·끝 슬래시를 포함해 원문 그대로 보존합니다. 키는 브라우저 저장소·프로젝트 JSON에 저장하거나 응답으로 돌려주지 않습니다.

현재 로컬 실연동에서 주소 검색은 성공했지만 필지·지적도 요청은 `INCORRECT_KEY`로 거부됐습니다. 원격 인증키 관리에 등록된 정확한 서비스 URL과 2D데이터/WMS 사용 설정을 확인해야 합니다. 이 인증 문제는 아직 해결 완료로 간주하지 않습니다. 자동 테스트는 공급자 응답 모의 데이터를 사용하며 실제 인증 성공을 보장하지 않습니다.

다음은 파일을 직접 편집하는 설정 방법입니다.

```powershell
Copy-Item .env.example .env
```

`.env`를 열어 다음을 입력하고 서버를 재시작합니다.

```dotenv
PORT=8791
VWORLD_API_KEY=발급받은_키
VWORLD_DOMAIN=http://localhost:8791
```

VWorld에서 실제 개발 도메인과 필요한 서비스 권한을 설정해야 합니다. UI의 ‘연결 설정됨’은 키가 존재한다는 뜻이며 실제 API 인증 성공을 뜻하지 않습니다.

연동 경로: `/req/search` 주소 검색, `/req/data`의 `LP_PA_CBND_BUBUN` 연속지적도, WMTS Base 지도. 서버가 공급자 요청을 중계하며 키는 브라우저나 프로젝트 파일로 보내지 않습니다. VWorld 키가 제공되지 않아 실제 인증·데이터 응답·약관/도메인 조건 검증은 아직 수행하지 않았습니다. 공급자에서 허용하는 활용·표시·저장 조건을 확인한 후 사용하세요.

선택된 Polygon은 선택점 기준 WGS84 지역 방위정거도법(AEQD, 미터)으로 변환합니다. 현재 구현은 단일 연결 Polygon만 받으며 MultiPolygon은 명시적으로 거부합니다. 계산 면적은 투영 경계 면적이며 공부상 면적이나 법정 대지면적을 대신하지 않습니다. 규제 자동 조회·확정은 미구현이므로 건폐율·용적률·높이는 사용자가 확인해 입력합니다.

## 계산 모델과 한계

이 앱은 **입력 조건 기준의 중복도형 배치 후보 탐색기**입니다. 인허가, 구조 안전, 피난, 일조, 주차, 세대 평면과 출입구 설계를 검증하지 않습니다.

1. 평지·단일 건물·단일 모듈 규격·동일 층간 반복 높이를 가정합니다.
2. 복도 양쪽에 같은 수의 모듈을 배치하고 단부에 코어 공간을 예약합니다. 코어 예약 길이 × 건물 깊이 전체가 공용공간으로 잡힙니다. 계단실 실제 설계가 아닙니다.
3. 0°/90°와 필지 장변 방향/직교 방향을 탐색합니다. 각 방향에서 배치 열 수 및 최대 25개 위치를 검사합니다. 전역 최적해나 임의 형상의 최대 매스를 보장하지 않습니다.
4. 회전된 건물 전체 외곽이 필지에 포함되는지 면적 교차로 검사하고, 모든 경계와의 거리를 검사해 이격을 적용합니다. 필지 구멍도 제외합니다.
5. 각 층은 온전한 모듈 쌍을 배치합니다. 상층부는 남은 용적률만큼 쌍 단위로 줄이며 아래층과 정렬됩니다.
6. 연면적은 공용공간과 접합 여유를 포함한 층 외곽 면적의 합으로 보수적으로 추정합니다. 용적률 제외 면적이나 법정 산정 예외는 반영하지 않습니다.
7. 건축면적은 상하 정렬된 후보의 가장 큰 층 외곽 면적입니다. 높이 외곽 토글은 선택 후보의 평면에 입력 최고높이를 적용한 참고선이며 모든 규정을 적용한 건축 가능 공간이 아닙니다.
8. 세대수는 단순 나눗셈 환산입니다. 실제 세대 조합/출입구/평면이 검증된 수치가 아닙니다.
9. 저층/작은 건축면적 대안은 최대 모듈 수의 80% 이상인 후보에서 각각 높이/건축면적을 최소화합니다. 조건에 따라 같은 후보가 선택될 수 있습니다.
10. 계산은 수평 범위 350m 이하, 면적 10~30,000㎡, 총 600개 이하 경계점으로 제한합니다. 서버는 로컬 127.0.0.1에 바인딩합니다.

## 검증

```powershell
npm test
npm run check
```

기하학적 포함/이격, 구멍·오목 대지, 회전 대지, 적층 정렬, 공용공간 충돌, 면적·높이 상한, 잘못된 입력 및 HTTP 엔드포인트를 검증합니다. 실제 VWorld 연동과 브라우저 GPU 렌더링은 이 자동 테스트 범위에 포함되지 않습니다.

## GitHub에 올리기

이 폴더만 별도 저장소로 올리면 됩니다. 참고 레포지토리와 분석 보고서는 포함할 필요가 없습니다. `.env`와 `node_modules`는 `.gitignore`로 제외되어 있습니다.

```powershell
git init
git add .
git commit -m "Add modular placement studio"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

위 명령의 계정·저장소 주소를 실제 주소로 변경하세요. 이번 작업에서는 원격 저장소 생성·업로드를 실행하지 않았습니다. 이 앱에는 Node 서버가 있으므로 GitHub Pages만으로는 전체 기능을 실행할 수 없습니다. 공개 서비스로 배포할 때는 서버 호스팅과 인증/호출 제한을 추가해야 합니다.
